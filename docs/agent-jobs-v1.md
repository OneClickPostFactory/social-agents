# Durable job identity and fenced execution — candidate

This source change pairs with the additive `20260928220000` migration owned by
`AyobamiH/oneclickpostfactory`. It is not a deployed or accepted product release.

All four scheduled enqueue paths use a database-owned operation identity.
Persisted fetch occurrence, queue-item/schedule occurrence, and date/inventory
revision identify distinct work. Duplicate deliveries reuse the record; different
parameters for the same identity are rejected. Active-work exclusion is atomic
across browser and scheduler callers. Enqueue and pending projection/cursor
advance share a transaction; replay cannot move the cursor twice.

Claims use caller-generated tokens and increasing fencing versions. Completion,
failure and recovery must prove exact tenant, job, token, version and live lease.
A retry of an already committed terminal outcome is allowed only if unchanged.
Scheduler result projection commits with terminal state and cannot replace a
newer job's projection. A periodic renewal does not resurrect an expired lease.

Expired execution can be claimed only in reconciliation mode. Recovery never
calls the original generation/publishing handler, releases angles from guessed
logs or creates another intent. Source/angle/publication ledgers remain separate
and authoritative for their own outcomes. Job fencing cannot recall requests
already in flight; durable generation-budget accounting remains a later slice.

Direct job-table mutation is revoked from browser and service roles. This is an
intentional fail-closed compatibility boundary: drain running jobs, apply schema,
verify `agent-jobs-v1`, then deploy the matching Worker. Legacy pending records
are preserved and can receive their first execution claim. Historical terminal
records are never relabelled or regenerated by this migration.

Do not roll back to an old raw-writing Worker while processing remains enabled.
A rollback must use a lease-aware compatible consumer or stop job processing;
do not restore broad DML grants to make an old Worker appear healthy. Source
merge does not authorise migration, deployment or provider activation.

Scheduling fairness, durable generation spending, connection-version fencing,
billing reconciliation and versioned content approval remain separate work.
A failed generation for an unchanged inventory revision stays terminal; inspect
or explicitly request new work rather than introducing automatic spend retries.

`test/agent-jobs.test.ts` exercises transport and wiring boundaries.
`test/agent-jobs-database.integration.ts` runs only against isolated local
Supabase/Postgres and forbids every external transport destination. It must pass
alongside the existing publication, concurrency and migration-history tests.
